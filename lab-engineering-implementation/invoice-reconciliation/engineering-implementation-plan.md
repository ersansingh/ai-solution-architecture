## 1. Purpose and Scope

This plan turns the approved design into a buildable, gated programme. It finds where the five inputs disagree, fixes the order of work around the riskiest assumptions, and gives each role a starting point.

**In scope** (BRD §3.1): discover documents in authorized Google Drive folders; process digital/scanned PDF, JPEG, PNG; extract and validate invoice/PO data; identify the PO; reconcile lines and financial amounts under approved tolerances; detect duplicates and anomalies; classify outcomes; keep evidence and traceability; safe reprocessing; expose results through the **existing** backend API.

**Out of scope / enforceable guardrails** (BRD §3.2). Each is a rule the build must enforce *and test*:

| ID | Guardrail | Enforced by | Test |
| :-: | :--- | :--- | :-: |
| GR-1 | No payments, bank transfers, ledger postings, payment approval | No such permission in any IAM role; no outbound integration to payment/GL systems | T-14 |
| GR-2 | Never modify source invoices/POs | Drive service account read-only; raw bucket write-once | T-14 |
| GR-3 | Never create or amend POs | PO source accessed read-only | T-14 |
| GR-4 | No automatic fraud determination | Anomaly codes carry "requires interpretation" wording; no `fraud` outcome exists | T-12 |
| GR-5 | No frontend | None built; exceptions surface via existing API/queue | n/a |
| GR-6 | No API contract change without approval | Contract tests pinned to the approved version | T-09 |
| GR-7 | Never invent a missing value | Extraction schema allows `unavailable` with reason; value must be traceable to page text | T-03 |
| GR-8 | Never auto-approve ambiguous/unsafe cases (BRD §11) | Single auto-reconcile gate in rules code, covered by property tests | T-11 |

**Team and constraints:** team size, day rate and deadline are **not given**. ASSUMPTION: 4-5 people at about 65% build focus (2 backend/AI engineers, 1 data/ML engineer, 1 DevOps part-time, 1 QA part-time) plus AP/Procurement SMEs part-time. Budget envelope from the strategy document: TCO $240k (capex $180k, 12-month opex $60k), released in four gates.

## 7. Data and Model Plan

- **Data sources and access:** Drive folders (read-only service account, M0-01); PO/supplier master (OD-1, M0-03); previous invoices for duplicate checks (ASSUMPTION: 12-24 months available; confirm in M0-02).
- **Data contracts:** versioned JSON schemas for extraction result, validated record, comparison result, outcome and evidence bundle. Missing data = `{"status":"unavailable","reason":"not_present|low_confidence|unreadable"}`; never null-and-continue.
- **Golden set:** target ≥500 documents (OD-10) covering digital PDFs, scans, images, credit notes, partial invoices, multiple POs, top suppliers; 10% double-labelled; split **by supplier** and by time; frozen at v1 after M1-01, v2 after pilot feedback; stored in S3 with versioning, access restricted (contains real financial data).

- **Versioning:** prompts, JSON schemas, policies and model IDs recorded on every decision; promotion Experimental → Staging (shadow) → Candidate (canary) → Production.
- **Metrics and targets (from algorithm report and strategy):**
