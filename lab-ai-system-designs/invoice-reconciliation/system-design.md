## 2. Architecture Pattern Selection

**Selected pattern: Hybrid — Document AI (transfer learning) + deterministic rules engine + optional predictive risk scoring.** Not an autonomous agent system.

```
Drive ─► Intake queue ─► Workflow (Step Functions)
                           │
           ┌───────────────┼──────────────────────────────┐
           ▼               ▼                              ▼
   Document AI        Rules / matching              Risk signals
 (Textract + LLM    (PO ID, lines, money,        (duplicates, Isolation
  verifier, schema)   tolerances: Decimal)        Forest → LightGBM)
           └───────────────┴──────────────┬───────────────┘
                                          ▼
                      Outcome + evidence ─► Backend API / Exception queue
```

**Rationale**
- **Document AI** is the only place ML is essential: pages vary by supplier and scan quality (see algorithm report, section 3).
- **Rules decide, models propose.** Financial outcomes need reproducible, versioned, explainable logic (BR-09, BR-11). An LLM never chooses a PO, never approves, and has no tool access.
- **Not RAG / not fine-tuned LLM / not multi-agent.** There is no knowledge-retrieval need. A multi-agent runtime would add non-determinism to a control process. The "agent" view is therefore a **deterministic supervisor with bounded workers** (page 8 of the diagram).

## 3. Architecture Reasoning

| Decision | Choice | Why |
| :--- | :--- | :--- |
| Cloud | **AWS** (single primary region + warm-standby DR) | Textract AnalyzeExpense and Bedrock are managed and in-region; the team already uses the AWS tooling in this repo. Azure Document Intelligence is an equivalent swap. |
| Orchestration | **Step Functions** (per-document workflow) | Built-in retries, catch, wait-for-human task tokens, audit history; deterministic. |
| Compute | **ECS Fargate** + Lambda (Drive watcher) | No servers to patch; scales with queue; Spot for batch. |
| Extraction | Textract first, Bedrock multimodal for low-confidence fields only | Cheapest reliable path; LLM cost limited to the hard fields. |
| Fallback | Textract → Bedrock A → alt model/region → self-hosted LayoutLMv3 → manual review | Never guess: the last stop is a human. |
| Results store | **Aurora PostgreSQL** (Serverless v2) | Relational integrity for outcomes, variances, anomaly codes; row-level security per legal entity. |
| Evidence | **S3 with Object Lock** | Tamper-resistant audit evidence (BR-11). |
| Idempotency | **DynamoDB** key = document hash + rule version | Prevents duplicate records on retry/reprocess (BR-10, BR-13). |
| Money math | `Decimal` in minor units, versioned tolerance/rounding policy | No float errors; policy supplied by Finance (BRD section 15). |
| Frontend | **None** | Out of scope; exceptions reach users through the existing API/queue. |

## 6. Interaction Flow

1. **Discover**: the Drive Watcher lists new/changed files in configured folders (read-only service account) and enqueues file events (BR-01).
2. **Gate**: the workflow computes the document hash and checks the idempotency table (hash + rule version). A duplicate event is a no-op (BR-10).
3. **Copy & classify**: the original is copied to the immutable raw bucket; the document is classified as invoice, PO, credit note or unsupported (BR-02).
4. **Extract**: Textract AnalyzeExpense returns fields, tables and confidence. Fields below threshold go to the Bedrock verifier, which returns schema-constrained JSON with the source location of each value (BR-03).
5. **Validate**: deterministic checks on mandatory fields, dates, currency, identifiers, and line sums vs subtotal vs total (BR-04). Missing values stay `unavailable`.
6. **Identify PO**: normalized PO number lookup, then supplier/date/amount candidate retrieval. **More than one plausible PO → Requires review**; no arbitrary pick (BR-05).
7. **Reconcile**: line matching by item ID, then embedding + Hungarian for the rest. Quantities (including previously invoiced), prices, discounts, taxes, charges and totals are compared under the active policy version, with currency compatibility enforced (BR-06, BR-07).
8. **Detect anomalies**: duplicate invoice, repeated billing, supplier mismatch, PO eligibility, etc., each with an explanation. Risk score (phase 3+) only orders the review queue (BR-08).
9. **Classify**: auto-reconcile **only if every mandatory check passes**; otherwise the outcome follows the exception policy (BR-09, BR-12).
10. **Persist**: write the outcome to Aurora and the evidence bundle (extracted values, matching IDs, comparisons, variances, rule/policy version, timestamps, failures) to S3 Object Lock (BR-11).
11. **Publish**: results are available through the existing backend API; exceptions go to the review queue with a Step Functions task token (BR-14).
12. **Learn & reprocess**: reviewer corrections feed the golden set. A policy change or source change can trigger authorised, idempotent reprocessing (BR-13).

## 11. CI/CD Pipeline

File: [`pipelines/ci-cd.yml`](pipelines/ci-cd.yml) (GitHub Actions, OIDC to AWS, no stored keys).

1. **test**: lint and type check, unit and property tests, **golden-set regression gate** (fails on any unsafe auto-approval or accuracy below 95%), Terraform fmt/validate.
2. **build-scan**: build, Trivy scan (fail on high/critical), push to ECR.
3. **deploy-staging**: Terraform apply, shadow-mode smoke test.
4. **deploy-prod**: manual approval (Finance Controller + Engineering), plan then apply.

The workflow assumes `tests/unit`, `tests/property`, `tests/golden`, `tests/smoke`, `requirements*.txt` and a `Dockerfile` that do not exist yet (no application code in this repo). The pytest flags `--golden-min-accuracy` and `--max-unsafe-approvals` are conventions to implement in `conftest.py`. Model/prompt/policy versions are promoted through the registry stages Experimental, Staging, Candidate, Production (page 10).

## 12. Operational Model

| Topic | Approach |
| :--- | :--- |
| **SLA / SLO** | **Not defined in the BRD; to be agreed.** Proposed starting points: 99.5% pipeline availability, p95 end-to-end under 15 min per document, exception queue median age under 2 business days. |
| **DR** | Warm standby region; proposed RTO 4 h / RPO 15 min (to be agreed). Aurora Global Database, S3 CRR, Route 53 failover, quarterly game days. |
| **Backup** | Aurora automated backups + PITR (14 days), DynamoDB PITR, S3 versioning; Object Lock on evidence; retention per approved audit policy. |
| **Failure handling** | Step Functions retry/catch, SQS DLQ with redrive tool, circuit breaker on LLM calls, idempotent replay, safe reprocess API. |
| **Fallback** | Textract → Bedrock model A → alt model/region → self-hosted LayoutLMv3 → manual review. Kill-switch drops the system to review-only. |
| **FinOps** | Doc-hash cache, Textract-first, LLM only for low-confidence fields, prompt caching, Fargate Spot for batch, S3 lifecycle, budgets and anomaly alerts, cost-per-invoice KPI. Running-cost planning figure from the strategy document: ~$60k/year (~$5k/month); the Terraform budget variable defaults to a $2,000/month placeholder for dev and must be set per environment. |
| **Governance** | Steering committee monthly; policy changes (tolerances, matching IDs, duplicate rules, credit notes, retention) approved by Finance Controller and versioned; model card + risk register; EU AI Act / ISO 42001 mapping (not a high-risk use case by default, to be confirmed by Legal). |
| **Safety / HITL** | Auto-reconcile only when all mandatory checks pass; ambiguity, low confidence, supplier mismatch, suspected duplicate, ineligible PO → human review; anomaly is never a fraud verdict. |
| **KPIs** | STP %, critical-field accuracy, PO-ID accuracy, unsafe approvals (target 0), reviewer override rate, cost per invoice, leakage prevented, queue age. |
